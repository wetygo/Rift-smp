# Test report — read before trusting anything

**Nothing in this project has been executed in Minecraft.** The sandbox that produced it has no route to Mojang's servers
(HTTP 403 from the proxy), so no server/client could be started. Everything below is *static analysis or model testing*. Treat the pack and
schematic as a carefully checked first build that still needs an in-game shake-down.

Raw output of every automated check is in `docs/TEST_RESULTS_AUTO.txt` (regenerated by `tools/build_all.sh`).

## B. Results
All checks pass at the time of the build (see `TEST_RESULTS_AUTO.txt` for the live counts). During development the checks found
and I fixed: unsupported signs/banners (glass behind them), a royal gate whose clear-planes were on the wrong side, a ramp that was one block
short of the throne room floor (player had to climb 2 blocks), a missing `door/royal_w6`, a pillar colliding with a gate, and a sign embedded in the ramp.

## C. NOT tested — risks, in the order I would check them

1. **Litematica pasting block entities.** Command-block text and sign text must survive the paste (creative + OP, "paste NBT"). After pasting, look at one gate command block.
2. **`enable-command-block=true`**. Without it nothing active works.
3. **1.21.11 syntax I could not execute**: game rule name `command_block_output`; item tags used by the sorter (`#minecraft:logs`, `planks`, `wool`, `sand`, `coals`, `swords`, `pickaxes`, `trimmable_armor`, …) — each category is its own function file so one wrong tag only disables that category; `execute if items block … container.N`, `item replace block … from block …`, `loot insert … mine …` (no tool argument), the `crafter` orientation state `down_north`, macro functions (`function … with storage …`), written-book `pages:["text"]`.
4. **Sorter**: moves stacks between hoppers with `item replace`; verify with a mixed stack of logs/stone/diamonds into the intake chests. If the alarm lamp lights immediately, `execute if items` is not matching (tell me which line).
5. **Door radius & timing**: iron doors open/close via a redstone block in the lintel slot, flipped every tick by a command block.
6. **Crafter compactors** need a rising edge; the pulse is 4 ticks on / 16 off. Check one with 9 iron ingots split across the 9 slots by the hopper.
7. **Crop plots**: harvest runs every 10 s; crops start at age 0 — bonemeal them to test.
8. **Rail ring**: powered rails with redstone blocks beneath; curved corners are plain rails (carts slow slightly).
9. **Blimp** (new, highest risk): display-entity transformation NBT, `teleport_duration`, `ride … mount` on armor stands, seat bookkeeping via `data entity … Passengers/RootVehicle`. Test: `/function riftbrek:admin/blimp_on`, stand at dock A.
10. **Chicken chambers**: dispenser fires wind charges into the chamber; behaviour of the charge against chickens is unverified.
11. Also untested: `loot insert … loot minecraft:entities/*` (B11 synthesis), `forceload add` with macro origin, shulker loader/unloader hoppers.
12. Performance: ~55 always-on command blocks (+ per-slot checks when the sorter holds items). Fine for a small server; verify TPS.

### Smoke test (≈15 min)
1. `/reload` → no red errors in the log; `/scoreboard objectives list` shows `rb_*`.
2. Register yourself + `royal` (INSTALL §5). `/trigger rb_req set 1` → book with your Minecraft + Discord names. `set 2` → kit; again → cooldown message.
3. Alt account (not registered): walk at the gatehouse — doors stay shut; the **Chunk Ban Square** warns, slows, ejects after ~6 s. Register the alt as visitor: gate opens for ~10 min, member doors stay shut.
4. `/function riftbrek:admin/lockdown_on` → doors close (royal still passes); `…lockdown_off`.
5. Revoke the alt → every door shuts at once; the stolen/old ID book is useless.
6. Storage Nexus intake chests → items appear in the B5 columns; fill a category's 4 columns to see overflow → MISC.
7. Smelter/compactor/crop-plot/rail/ice/chicken-chamber quick checks from §C.

## D. Old data-pack defects that were fixed
1. Every kit file used unquoted namespaced SNBT keys (`enchantments={minecraft:protection:4,…}`) which do not parse in 1.21.x — a function with a parse error does not load, so **no kit worked**.
2. "Access doors" only set a tag for one tick (`rb_gate_ok`, cleared by `tick`) and produced **no redstone output**. Replaced by command-block gates that flip a real redstone block next to real iron doors; lockdown-aware.
3. Players could not run anything (`/function` needs OP). Added `/trigger rb_req` entry points.
4. Books were static text without usernames and could not carry per-player data; registry/roster only listed *online* players. Now a persistent registry (storage) + macro-built books (Minecraft + Discord names for non-Veil, operative code only for Veil).
5. No credential-id issuance, no ledger, no kit cooldown, shields had no banner colour, teams/nametags unused. Added.
6. `rb_secure` was never set automatically, so the visibility rule never ran. Replaced by zone functions run from command blocks.
7. `load` could not be re-run safely and lockdown/next-id state had no defaults. Now idempotent: never resets player data.
8. `internal_*` functions were advertised as callable and bypassed checks; now `_`-prefixed helpers + `*_apply` run only through checked entry points.
