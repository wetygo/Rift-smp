# RIFTBREK Vanguard data pack — specification for a data pack developer

Target: **Minecraft Java 1.21.11** (data pack format 94.1; `pack.mcmeta` uses `min_format`/`max_format` = `[94,1]`). Namespace **`riftbrek`**. Singleplayer world opened to LAN / "Essential" multiplayer, cheats on, command blocks enabled. Only two vanilla tags are used: `#minecraft:load` → `riftbrek:load`, `#minecraft:tick` → `riftbrek:tick`.
Reference implementation: `dist/RIFTBREK_Vanguard_Datapack.zip` (763 functions, generated by `tools/riftbrek/*.py`). Full per-function list: `docs/COMMAND_HANDBOOK.md`.

## 1. Purpose
Server-side "operating system" for the RIFTBREK Vanguard headquarters (a huge base with six factions): identity/credentials, access-controlled doors, kits, anonymity for one faction (Veil), messaging, lockdown, item sorting and farms, a moving blimp, and a member-quarters system (alarms, mail, privacy, launchers). The base itself is a schematic; the pack drives it through command blocks, entities and storage.

Factions (key / name / code / team colour): `birds` The Biggest Birds BB light_purple · `unstables` The Unstables UN blue · `abstracters` Abstracters AB dark_gray · `veil` Veil VL dark_purple · `archivist` The Archivist AR white · `wildcards` Wildcards WC aqua.
Clearance ladder (`rb_clear`): 1 visitor · 2 member · 4 leader · 5 royal. The King / owner ("wetygo") is Royal.

## 2. State
Scoreboards (all `dummy` except the trigger): `rb_cred` credential id (0 = none/suspended) · `rb_clear` clearance · `rb_role` faction number 1–6 · `rb_id` (+ fake player `#NEXT` = next id, starts 1000) · `rb_visitor` guest minutes/ticks left · `rb_kit`, `rb_lastkit` kit cooldown · `rb_issued`, `rb_denied`, `rb_incident` counters · `rb_lock` (`#GLOBAL` = lockdown flag) · `rb_msg` (`#VER` bulletin version, `#NEW`/`#INT` timers) · `rb_msgcd` message rate limit (2 s) · `rb_cbs` chunk-ban cooldown · `rb_bl` blimp (`#ON`, `#SPAWNED`, `#PH`, `#T`) · `rb_const` constants (#20 #200 #100 #2 #600) · **`rb_req` = `trigger`** (re-`enable`d for every player every tick).
Tags: `rb_<faction>`, `rb_leader`, `rb_royal`, `rb_veil`, `rb_guest`, `rb_revoked`, temporary `rb_kit_ok`.
Storage: `riftbrek:registry` (`roster` list, `players` map keyed by Minecraft name: mc, discord, faction, credential id, rank, status active/suspended/revoked), `riftbrek:log` `entries`, `riftbrek:msg` (`history` last 20, `lines` 4-line bulletin text), `riftbrek:cfg` `origin {x,z}` (world X/Z of the schematic's local 0,0; set once by an operator, used by macros).
Teams: one per faction (colour above) + a Veil team with hidden nametags and no collision.
`load.mcfunction` creates objectives/constants idempotently (never resets player data), initialises storage only if missing, runs `setup/teams`, `setup/gamerules`, and prints "[RIFTBREK] Vanguard datapack loaded." `tick.mcfunction` enables `rb_req`, dispatches `rb_req` requests, keeps Veil invisible, counts down visitor/cooldown/message timers, and calls the sub-systems below.

## 3. Player interface — `/trigger rb_req set N` (no OP; every action re-validates server-side)
1 issue ID book (non-Veil: MC + Discord name, faction, rank, clearance, id; Veil: anonymous operative code `RB-VL-<id>` only; a book never authorises anything) · 2 own faction kit (10-min cooldown, Royal bypass) · 3 public roster (never lists Veil) · 4 leader registry incl. Veil ledger (leader/royal only, private output) · 5 my status · 9 help · 11–16 six "creator-inspired" kits (members) · 30–37 radio presets (backup, all clear, intruder, meet at plaza, need supplies, heading out, medic, lockdown requested) · 40/41/42 book message (written from a Book & Quill, page 1) to own faction / all members / leaders · 43 announcement (leader/royal: title + bell for everyone + all bulletin-board signs update) · 44 last-20 history (own faction only) · 45 replay last announcement.
Rules: strangers, revoked, suspended and visitors cannot send; max 1 message / 2 s; Veil senders appear only as operative code (never `@s` in output, no name leaks); leaders channel blocked for plain members.

## 4. Operator interface (`/function`, OP ≥ 2)
`admin/register {mc,discord,faction}` (online player: id, tags, team, clearance 2, registry record, log entry) · `leader` / `unleader` / `royal` / `unroyal {mc}` · `revoke {mc}` (strip everything, credential 0, status revoked) · `revoke_credential {mc}` (suspend only) · `restore {mc}` · `visitor {mc,…}` / `visitor_grant` (timed guest pass; `visitor/expire` clears it) · `whois`, `incident`, `recover`, `reset_cooldown`, `gate_test` · `lockdown_on|off` (sets `#GLOBAL rb_lock`, title + bell siren, doors close except for Royal) · `origin {x,z}` · `forceload` / `forceload_off` (force-loads sorter halls, industry, synthesis hall, blimp lane, checkpoint relative to origin) · `blimp_on|off` · `board_refresh` · `verify` (9 block probes at origin-relative positions; expects all PASS) · `paste/init`, `paste/zone_N_tp|on|check|off` (24 forceload zones for pasting the schematic).

## 5. Access doors
Each door gate is an always-running (repeating) command block with a "power slot" directly **below** it: `redstone_block` = open, `iron_bars` = closed (this drives real redstone/pistons in the build). Tiers: `birds, unstables, abstracters, veil, archivist, wildcards, member, leader, royal` × widths 1 / 6 / 12 (`<tier>.mcfunction`, `_w6`, `_w12`; detection radius 3 / ~6 / 9). Open if a player in radius has the faction tag, not `rb_revoked`, `rb_cred ≥ 1`, `rb_clear ≥ 2` (leader ≥ 4, royal ≥ 5) **and** no lockdown; Royal always opens; lockdown closes everything except for Royal. Veil secret tunnels use the veil tier. Invalid/stolen books never open anything — only tags + scores count.

## 6. Veil anonymity (design intent)
Veil members: permanent invisibility effect (re-applied every tick), hidden nametag team, operative code instead of names in books/messages/logs. `zone/visible*` makes them visible only to other Veil. Known limits (cannot be fixed in a pack): vanilla `/msg`, tab list, join/leave messages still show names.

## 7. Kits
`kit/<faction>` checks tag + credential + cooldown (`_cooldown_check` → `rb_kit_ok`) then `kit/internal_<faction>` gives faction gear; six creator-inspired kits (`creator_flame/wemmbu/theobald/parrot/manepear/spoke`). Enchantments must use valid 1.21 component syntax with **quoted** keys, e.g. `minecraft:enchantments={levels:{"minecraft:protection":4}}`.

## 8. Message system
Presets, book messages (read `SelectedItem.components."minecraft:writable_book_content".pages[0]`, string or `{raw:…}`), announcement with bulletin-board refresh (signs in the base are rewritten with `data modify block … front_text.messages`), history and last-announcement, all in `msg/*`. Quick radio lines come from `msg_system` quick_0–7.

## 9. Storage / industry (command-block driven)
`storage/a|b/cNN_sS` + `hall_x_slot_N`: two sorter halls. A tray hopper slot is inspected with `execute if items block ~ ~ ~1 container.0 <item>`; if the matching category chest slot is free (`unless items block … *`) the stack moves with `storage/move {dx,dy,dz,s}` (`item replace … from block`). Categories use explicit item-id lists (logs, planks, wool, carpets, sand, coals, terracotta, saplings, leaves, flowers, swords/pickaxes/axes/shovels/hoes, armor, arrows, ores, food, …); overflow bin + alarm lamp. `industry/*`: crop plots (wheat, carrots, potatoes, beetroot; `farm_tick`, `run_farm_*`), `pulse_crafter` (autocrafter pulse 4 on/16 off), synthesis hall `synth_*` (iron, gunpowder, bones, string, flesh, blaze, pearls, witch loot via `loot insert`). Positions are relative to command blocks or to `riftbrek:cfg origin` (macros `$(x) $(z)`).

## 10. Blimp (Airlander 10, built by Krodo)
`blimp/spawn` summons ~1,900 `block_display`/`item_display` entities (from a box list) + 6 seat armor stands tagged for the ship; `blimp/run` moves the hull along a N–S lane at x=250 (docks at z 110 / 480 / 700) with `teleport_duration` interpolation (hull every 2 ticks, seats every tick); `board`, `mount` (`ride … mount`), `left`, `next` (next dock), `move_n/s`. Controller = repeating command block under dock A; switched with `admin/blimp_on|off`; docks close during lockdown.

## 11. Member quarters (BAT-style)
22 numbered rooms (local x 478..526, z 568..593, 3 floors). `alarm/room_N`, `alarm/all`, `alarm/reset`, `alarm/emergency_N`, `alarm/ring_here` (red title + bell only to players inside the room / everyone); `alarm/intrusion` (+`_fire`, 10 s cooldown) fired by sculk-sensor impulse blocks when a non-member crosses the perimeter; `mail/room_S_slot_s` + `mail/move`: dispenser mailbox — a written book whose title or custom name equals a room number moves to that room's dispenser (same slot, kept if occupied, unknown numbers stay; the pack matches four possible title encodings); `privacy/room_N`: lever → fills the window gap with lava (glass / lava / glass); `launch/pad|go|no_elytra`: member wearing an elytra is launched 1,000 blocks straight up (`tp @s ~ ~1000 ~`, slow_falling 6 s); no elytra / non-member / revoked / visitor = nothing.

## 12. Hard requirements for any re-implementation
- Pure vanilla datapack, 1.21.11 syntax (functions in `data/<ns>/function/`, tags in `data/minecraft/tags/function/`); no mods.
- `/function` is OP-only, so players interact through triggers and command-block-driven devices; command blocks inside the schematic call functions (some with macros: `function riftbrek:x with storage riftbrek:cfg origin`).
- Idempotent `load`; never wipe registry/scores on `/reload`.
- Every privileged function re-checks tags/scores; revoked players keep nothing.
- Must tolerate chunks not loaded (use origin + forceload, fail soft).
- Gamerules set on load: command block output off, announce advancements off (rule names changed in 1.21.11 — set by hand if `/reload` complains).
- Verification: `admin/verify` should report 9 PASS when the schematic is pasted at the configured origin.
