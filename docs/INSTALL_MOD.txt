RIFTBREK Vanguard - MOD package v1.0.7  (Minecraft Java 1.21.11, Fabric)
=========================================================================
The mod CONTAINS the data pack. Do NOT also install the separate data pack zip.

WHAT YOU STILL NEED (not in this zip)
  * Minecraft Java Edition 1.21.11 (the launcher's own Java 21 is fine; to double-click fabric-installer.jar you need Java 21 on the PC)
  * Internet for the Fabric installer (it downloads the Fabric loader profile + libraries) and for Minecraft's first launch of that profile
  * Fabric Loader 0.17.3 or newer (the installer gives you the latest; the bundled Fabric API 0.141.6 needs >= 0.17.3)

IN THIS ZIP
  fabric-installer.jar                         installs Fabric Loader for Minecraft 1.21.11
  mods/fabric-api.jar, mods/riftbrek-vanguard-1.0.7.jar    put both in .minecraft/mods
  standalone_world/RIFTBREK_Vanguard_World/    a ready world (void) with the base - option A
  base_files/region + base_files/entities      the WHOLE HQ: original base + annex + OUTER WARD + the Pipeline ring (X 7680..13327, see docs/OUTER_WARD.md) - options B / C
  ithaca_files/region                          ITHACA CITY (placed at X 12288, Z 8192; files r.24.16 r.24.17 r.25.16 r.25.17) - same options
  docs/ITHACA_CITY.md, docs/LAUNCHER.md        what Ithaca contains, what is NOT built, coordinates; the chicken launcher
  MergeBase.java                               adds the base into an EXISTING world without losing other chunks - option C

1) INSTALL FABRIC + THE MOD (always)
   a. Run fabric-installer.jar -> Client -> Minecraft 1.21.11 -> Install. Start the launcher once, choose the new "fabric-loader-1.21.11" profile, then quit.
   b. UPGRADING? First DELETE any older riftbrek-vanguard-*.jar (1.0.0 / 1.0.1) from .minecraft/mods - two jars with the same mod id stop the game from starting.
      Then copy the two jars from this zip's mods folder into .minecraft/mods (create the folder if missing). Essential for Fabric can be installed next to it.

2) PUT THE BASE IN A WORLD - pick ONE option. BACK UP YOUR WORLD FIRST.
   A. NEW WORLD (zero risk to your old world, cannot collide): copy standalone_world/RIFTBREK_Vanguard_World to .minecraft/saves/ and open it from Singleplayer. Cheats are already on.
   B. EXISTING WORLD, no name collision: in your world folder check that these do NOT exist
        region/:   r.15.15 r.15.16 r.15.17 r.15.18 r.16.15 r.16.16 r.16.17 r.16.18 r.17.15 r.17.16 r.17.17 r.17.18 r.18.15 r.18.16 r.18.17 r.18.18 r.19.15 r.19.16 r.19.17 r.19.18 r.20.15 r.20.18 r.21.15 r.21.18 r.22.15 r.22.18 r.23.15 r.23.18 r.24.15 r.24.18 r.25.15 r.25.18 r.26.15 r.26.16 r.26.17 r.26.18
        entities/: r.18.17 r.19.16 r.19.17
      If none exist, copy base_files/region/* and base_files/entities/* into your world's region/ and entities/ folders.
   C. EXISTING WORLD, some of those names exist (normal - the file also holds YOUR chunks): use the merge tool. The base covers the WHOLE area
      The enlarged HQ covers X 7808..10111, Z 7808..9343 (2304 x 1536 blocks, every height): the original 768 x 768 base in the middle, the annex to its east and the outer ward north, south and west of them; the Pipeline wall (X 7680..13327, Z 7680..9487) surrounds it and Ithaca.
        Close Minecraft. Open a terminal in this zip's folder and run (Java 21):
          java MergeBase.java "<path to your world folder>" base_files --dry-run      <- plan only; writes NOTHING (no files, no folders)
          java MergeBase.java "<path to your world folder>" base_files               <- applies it
        What it does: validates every file first (a corrupt file aborts before anything changes); adds the base's chunks into your region files and keeps
        every other chunk; STOPS without changing anything if your world already has DIFFERENT chunks where the base needs to go (it lists them).
        Only if you accept losing those chunks add  --replace-existing . Changes are applied with rollback (a failure restores everything). Backups of every
        changed file go to a NEW folder  <world>/riftbrek_backup_<date-time>/  each run (older backups are never overwritten). Re-running is safe: already
        installed chunks are recognised and nothing is rewritten.
   D. Need a different spot altogether: tell me the coordinates and I re-export; /rift origin only tells the mod where the files are, it does not move them.

3) FIRST START
   Open the world with the Fabric profile. The mod auto-loads the data pack, sets the origin (X 8192 Z 8192 - the ORIGINAL base's corner; the ward is positioned around it) and force-loads the machines (about 382 chunks).
   Wait a few minutes for lighting. Cheats must be on (new world: already; existing: open to LAN with cheats).
   /tp @s 8575 33 8932
   /rift verify          -> 9 / 9 PASS (the mod loads the check chunks itself, so it works from anywhere, in any dimension)

4) FIRST USE (OP / cheats)
   /function riftbrek:admin/register {mc:"YOURNAME",discord:"yourdiscord",faction:"birds"}
   /function riftbrek:admin/royal {mc:"YOURNAME"}
   Players: /trigger rb_req set 1 (ID book), 2 (kit), 9 (help).  Unknown faction names are rejected before anything changes.

ITHACA CITY: install ithaca_files/region exactly like the HQ files (option B: check r.24.16 r.24.17 r.25.16 r.25.17 do not exist; option C: java MergeBase.java "<world>" ithaca_files --dry-run).
   The standalone world already contains BOTH the HQ and Ithaca. Then:  /tp @s 12672 33 8917   /rift verify city   (expect 9 / 9 PASS)
   Ithaca sorter chunks are force-loaded by the mod (autoCity=true). Different place: /rift city <x> <z> only tells the mod where the files are.

CONFIG:  config/riftbrek.properties (originX, originZ, autoForceload, cityX, cityZ, autoCity).  /rift origin <x> <z> saves it and moves the force-loads. The mod only removes force-loads it added itself (recorded in <world>/riftbrek_forceloads.json); chunks an admin or another mod force-loaded are never touched. (The data pack's own admin/forceload_off command removes everything in the base's areas - use it only deliberately.)
